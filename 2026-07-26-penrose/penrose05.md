## ペンローズタイリングを黄金比のひし形に置き換えると高次元が見える ── カット・アンド・プロジェクト法

![](https://static.zenn.studio/user-upload/326e679d8196-20260815.png)


## 五角形のままでは見えないもの

これまでの記事では、ペンローズ構造を**正五角形を敷いた図**として扱ってきた。十角形の穴を10枚の五角形が囲む「円環」を単位にして、円環をつなぎ、隙間として細ひし形・五芒星・舟・正十角形が出てくる、という組み立て方である。

この図は、そのままでは高次元と繋がらない。

繋げるには、**同じ図をひし形に置き換える**必要がある。ひし形にすると、平面の図が高次元の格子の影であることが見えてくる。これがカット・アンド・プロジェクト法である。

この記事は、その置き換えを実際にやってみた記録である。借りてきた道具（1981年の定理）と、こちらで測った数値を、はっきり分けて書く。

---

## 借りてくるもの：de Bruijn の指数と窓

N.G. de Bruijn は 1981年の論文 *Algebraic theory of Penrose's non-periodic tilings of the plane I・II* で、ひし形版のペンローズタイリングを完全に代数化した。使うのは次の二つだけである。

### 指数

$\zeta = e^{2\pi i/5}$ とする。ひし形の頂点はすべて

$$
k_0 + k_1\zeta + k_2\zeta^2 + k_3\zeta^3 + k_4\zeta^4 \qquad (k_j \in \mathbb{Z})
$$

の形に書ける。ここで **$r = \sum_j k_j$ を指数と呼ぶ**。

$1+\zeta+\zeta^2+\zeta^3+\zeta^4 = 0$ なので $\sum k_j$ は 5 を法にしてしか決まらないが、de Bruijn はこう証明している。

> **指数は 1, 2, 3, 4 のいずれかにしかならない。0 にはならない。**

これが効く。後で見るように、**指数が 0 の点は、どんなタイリングでも頂点になりえない**。

### 窓

そのうえで、点が実際に頂点として現れる条件が定理 8.1 である。

$$
\Big(\textstyle\sum_j k_j,\ \sum_j (k_j-\gamma_j)\zeta^{2j}\Big) \in V
$$

$\gamma_j$ は図をずらすパラメータ（和は 0）。$\sum(k_j-\gamma_j)\zeta^{2j}$ を**残渣**と呼ぶことにする。実空間の位置とは別の、もう一枚の平面の上の点である。

$V$ は指数ごとに四つの五角形に分かれる。

| 指数 | 窓 |
|---|---|
| 1 | 頂点 $1,\zeta,\zeta^2,\zeta^3,\zeta^4$ の五角形の内部 |
| 2 | 頂点 $1+\zeta,\ \zeta+\zeta^2,\ \dots$ の五角形の内部 |
| 3 | $-V_2$ |
| 4 | $-V_1$ |

**ある点が図に現れるかどうかは、その残渣が自分の指数の窓に入るかどうかだけで決まる。**これがカット・アンド・プロジェクトの中身である。実空間は無限に広がるが、残渣は五角形の中に閉じ込められている。

窓を動かすと図がどう変わるかは、触ってみるのが早い。

図1：5角形10個の円環を繋いだペンローズタイリングは、黄金比のひし形からできたペンローズタイルに置き換えることが出きる。（Penrose cap.HTML）

## 手元の表現へ移す

こちらの計算は $\zeta_{10} = e^{i\pi/5}$ の4成分 $(a_0,a_1,a_2,a_3)$ で持っている。$\zeta_{10} = -\zeta_5^3$ なので、対応はこうなる。

```
指数     Σk_j = a₀ − a₁ + a₂ − a₃   (mod 5)
残渣     w = Σ a_k ζ₁₀^{7k}
```

**指数は交代和である。**これは整数の足し算だけで出る。以下の数値はすべて $\mathbb{Z}[\varphi]$（$\varphi^2=\varphi+1$）の厳密演算で、浮動小数は画面に落とすときにしか使っていない。

### 検算（先に置く）

数値を出す前に、実装が正しいことを別ルートで確かめておく。ペンタグリッド（§5 の構成）から頂点を作り、§8 の窓判定に当てる。

```
正則ペンタグリッドから作った頂点 995 個 → 窓の中 995／外 0     OK
指数の分布 {1:121, 2:373, 3:377, 4:124}   → 0 が出ない        OK
対照：同じ指数を持つ勝手な k ベクトル 3171 個のうち窓の中は 46 個（1.5%）
```

対照が 1.5% まで落ちるので、この検査は**失敗を返せる**。これを確かめずに先へ進むと、通って当たり前の検査を「確認」と読んでしまう。

## 測った結果

910個の円環でできた図（五角形6030枚）の点を、三種類に分けて窓に当てた。$\gamma = 0$、つまり10回対称の位置である。

```
円環の中心    910 個 → 指数3。910 個すべてが窓の中          全部が頂点
五芒星の中心  416 個 → 指数0 が 211 個  頂点になりえない
                      指数1 が 205 個（窓の中 185・外 20）
五角形の中心 6030 個 → 指数2：中 2905／外 110
                       指数4：中 1925／外 1090
```

この三つは、二枚を並べて見ると一目でわかる。

** 図2：五角形の円環と黄金比のひし形の比較**（Compare center.HTML）

@[codepen](https://codepen.io/editor/morcb13-bit/pen/019ffdc0-a3b5-7ec1-81df-bf87a17872b6?default-tab=result)

*左が五角形の図、右が de Bruijn のひし形。原点も倍率も共通で、ドラッグとホイールが連動する。「両方を1枚に重ねる」で重ね合わせに切り替わる。緑（円環の中心）は必ずひし形の頂点に乗り、赤（五芒星の中心）は乗らない。*

### 円環の中心は、例外なくひし形の頂点だった

ずらしも尺度合わせも要らない。910個すべてが指数3 で、すべてが窓 $V_3$ の中にある。

**五角形を敷いた図の円環中心は、そのままひし形版の頂点集合に含まれている。**

### 五芒星の中心は、原理的に乗れない

416個のうち 211個は指数が 0 である。de Bruijn の定理により、指数0 の点はどんな $\gamma$ を選んでも頂点にならない。五芒星は隙間なので、ひし形が埋めている場所に当たる ── むしろ乗らないほうが自然である。

### 五角形の中心と「番地の偶奇」

五角形の中心 6030枚の指数を見ると、きれいに割れた。

```
指数2 が 3015 枚 ⟺ 向きラベルが偶（例外なし）
指数4 が 3015 枚 ⟺ 向きラベルが奇（例外なし）
```

こちらの図では、五角形を敷くときに「同じ位置でも番地の偶奇が合えば置いてよい」という規則を使っている。**その番地の偶奇が、de Bruijn の指数そのものだった。**1981年の論文と同じ量を、別の経路で使っていたことになる。

## 逆は成り立たない

ここは正直に書いておく。

```
実半径62 までの指数3 の格子点
  円環かつ窓の中     490
  円環だが窓の外       0
  円環でないが窓の中 4590   ← ここ
```

**円環中心はひし形の頂点だが、頂点のほうが9倍多い。**包含であって一致ではない。窓 $V_3$ を相似に縮めて円環だけを切り出せないかも調べたが、実半径22 の時点で円環側の最大と非円環側の最小が交差する。**どんな相似縮小でも分離できない。**

つまり「円環中心とは何か」は、de Bruijn の窓だけでは書けない。ここは未解決である。

## 3次元では、窓が菱形三十面体になる

同じ構図が3次元にもある。2次元で窓が五角形だったところが、3次元では**菱形三十面体**になる。この図をドラッグして回転させてみてください。

**図3：菱形三十面体は自在に回転できる**（t30 viewer.HTML)
@[codepen](https://codepen.io/editor/morcb13-bit/pen/019ffda9-74ec-7c61-80c3-55db7559f076?default-tab=result)


*ドラッグで回せる。右の「帯を選ぶ」で6本を切り替えると、どの面も必ず2本の帯に属していることが見える。*

正20面体の5回対称軸6本を生成ベクトルに取ると、面が30枚のゾーン多面体ができる。すべての面が黄金菱形である。これも整数で確かめられる。

```
生成ベクトルの長さ² = 2 + φ（6本とも同じ）
面はすべて4辺が等長
対角線² = 4  と  4 + 4φ      比² = 1 + φ = φ²   →  比 = φ ちょうど
頂点 32（20個 + 12個）＝ 正12面体の頂点20 + 正20面体の頂点12
```

比が $\varphi$ になることが、近似ではなく**等式**として出る。

### 帯（zone）が、円環に対応する

生成ベクトル1本を選ぶと、それに平行な辺を持つ面が10枚ある。これが**帯**である。

上の観察台で「帯だけ表示」にすると、10枚が単独で見える。帯の軸まで回すと10枚が全部つぶれて十角形になり、少し傾けると菱形が戻る。

```
生成ベクトル 6本 → 対の数 15 → 各対に表と裏の2枚 → 面 30 枚
帯は生成ベクトル1本につき1本 → 6本、各10枚
6 × 10 = 60、各面は2本の帯に属するので 30 枚
```

**帯10枚が、平面の円環10枚に対応する。**帯の軸方向から見下ろすと、10個の位置が半径一定・方位 0°, 36°, 72°, …, 324° の**正十角形**に並ぶ。平面の円環（10枚の五角形が36°刻み）と同じ配置である。

なお、軸に沿って見ると帯の10枚はすべて線分に潰れて十角形の輪郭だけが残る。菱形として見るには斜めから見る必要がある。

## 何が言えて、何が言えないか

確定したこと。

- ひし形の頂点は、指数と窓で完全に決まる（995/995、対照は 1.5% に落ちる）
- こちらの図の円環中心は、910個すべてがひし形の頂点である
- 番地の偶奇は de Bruijn の指数である（6030/6030、例外なし）
- 五芒星の中心は、半分が指数0 で、原理的に頂点になりえない
- 3次元の窓は菱形三十面体で、その帯10枚が平面の円環10枚に対応する

**まだ言えないこと。**

- 円環中心を窓から切り出す条件（$V_3$ の相似縮小では不可能と分かっただけ）
- 五角形の中心の受容集合（半径を変えると境界が動くので、形をまだ推定できない）
- こちらの図が、de Bruijn の族のどこに座っているか

### この記事が倒れる条件

- 円環中心のうち1個でも窓の外に出れば、中心の主張は倒れる
- 番地の偶奇と指数の対応に1件でも例外が出れば、対応の主張は倒れる
- 菱形三十面体の対角線比が $\varphi$ でなければ、3次元側は全部倒れる

いずれも整数の等号で検査できる。反証したい方は、そこを狙ってほしい。

## 追記 ── 3次元でも、窓は目の前にある

**図４：菱形三十面体の輪を積んだ管**  ── Kabai–Bérczi 2009 p.100 を参考にした再現

@[codepen](https://codepen.io/editor/morcb13-bit/pen/01a002a3-d426-7a1b-9cbf-1ee5e95c556e?default-tab=result)

ここまでは平面の話でした。ひし形の頂点を選ぶ受容窓は、de Bruijn の五角形 V_r でした。

3次元に上げると、窓は**菱形三十面体（rhombic triacontahedron, 以下 RT）そのもの**になります。6次元の立方格子を正20面体対称に切ったとき、単位立方体を残渣側へ落とした影がちょうど RT です。平面で「窓は五角形だ」と言ったのと同じ意味で、空間では「窓は RT だ」と言えます。

面白いのはここからです。**窓である RT は、そのまま積み木にもなります。**

Sándor Kabai と Szaniszló Bérczi は『Rhombic Structures』(2009) で、RT を面どうしで繋いで輪を作り、その輪を積むと閉じた管状構造になることを図示しています（p.100）。本稿の以下は、その構成を参考にして、こちらで組み直したものです。

### 一歩を整数にする

RT の面は30枚あり、どれも黄金菱形です。隣の RT を面で貼り付けると、中心はある決まった量だけずれます。

このずれを3次元の実数ベクトルとして扱うと、輪が閉じるかどうかが誤差の話になってしまいます。そこで**6次元の側で数えます**。

- RT は生成子6本のゾノトープなので、面の法線は生成子2本の外積で決まる
- 面を貼るときの一歩は、**その面を張らない残り4本の生成子を ±1 ずつ足したもの**
- つまり一歩は「±1 が4つ・0 が2つ」の**整数ベクトル**

一歩は30本あります（面30枚に対応）。そして、

> **輪が閉じる ⟺ 使った一歩の総和が6次元でちょうど 0**

これは整数の足し算です。丸めも許容誤差も入りません。

さらに、72°の回転は6次元では**符号つきの置換行列** g になります（g⁵ = I が整数のまま成り立つ）。5回対称の輪を探すなら、区画ひとつぶんの歩みを決めて g で5回まわせばよく、探索空間は一気に小さくなります。

### 何が出たか

**計算：**面接触の一歩30本すべてで、その面の法線だけ支持値ちょうど（＝接する）、他14本は支持値未満（＝食い込まない）。

**計算：**5回対称の輪で、閉じてかつ重ならないものは次のとおり。

| RT の個数 | 成立した歩みの組 |
|---|---|
| 5 | 10通り |
| 10 | 90通り |
| 15 | 1230通り |

どれも中心間の最小距離は **2.752764** で、これは面接触の一歩の長さそのものです。つまり隣どうしはぴったり接していて、どこも食い込んでいません。

**計算：**RT 1個は、尖った菱形六面体10個と平たい菱形六面体10個の計20個に分かれます。

**見立て：**穴が見えるのは15個の輪です。10個では穴が塞がって塊になります。

**図5：更に菱形三十面体の輪を積んだ管 15個の輪 × 10層＝150個**

@[codepen](https://codepen.io/editor/morcb13-bit/pen/01a002e9-1ff9-7e1a-8c55-5b43b703db81?default-tab=result)

### 検査が落ちうることの確認

閉じる歩みの組のうち、**立体としては重なってしまうものが1390件**ありました。代数が閉じても立体が通るとは限らないということで、重なり判定は実際に仕事をしています。判定は「2つの中心の差が 2·RT の内部に入らないこと」で、これも支持関数だけで書けます。

### 倒れる条件

次のどれかが示されたら、この節は倒れます。

1. 一歩の総和が 0 でないのに閉じる輪が存在する（＝6次元の判定が輪の条件になっていない）
2. ここで成立とした輪のどれかで、2つの RT が実際には食い込んでいる
3. 5回対称を課さずに探すと、5・10・15 以外の個数の輪が出る（本稿は5回対称を仮定した範囲しか掃いていない）

3 は否定ではなく、**まだ掃いていない**という意味です。

### 再現できていないこと

Kabai–Bérczi の p.100 には「90 prGR の環」「190 prGR の環」という数え方が出てきます。あちらは**尖った菱形六面体（prolate golden rhombohedron）を単位に数えている**のに対し、本稿は **RT を単位に数えています**。同じ物体を別の粒度で数えているのか、そもそも別の物体なのかは、まだ確かめていません。上面図に現れる20方向の星は、prGR の側から組まないと出てこないはずです。
