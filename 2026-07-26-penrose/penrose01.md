## 原点は紙の上にあった

**（図１）手書きで5角形10個を並べていった図（中心部分）**
![](https://static.zenn.studio/user-upload/2b9e708a40bf-20260726.png)

B13の出発点は、定理でも予想でもない。5角形を10個、輪にして並べた図である。

正五角形を10枚、辺を合わせて環にすると、真ん中に穴が空く。この環をいくつも並べていくと、中心に五芒星が立つ。これをプロセッサの芯にする——その発想は最初からあった。2026年2月、手描きとCADで確認した。平衡5進数（2歩戻ることが負の桁の加算になる）で環が閉じることに気づいたのも、AIではなく紙の上だった。

そこから残渣が出て、着地が出て、番地が出て、いまのB13になった。数論の側にずいぶん深く入り込んだので忘れそうになるが、材料は最初から五角形10個だった。

## AIは図形の認識は苦手である

最初に判明したのは、AI側が持っていた環の定義が誤っていたことだ。

環の半径を、隣り合う五角形の中心間距離が**辺の長さ**になるように取っていた。しかし五角形が辺を共有するとき、中心間距離は辺の長さではない。内接円半径の2倍である。

> **観察者側の整理**（借用した知識としてラベルしておく）
> 外接半径 1 の正五角形の内接円半径は cos(π/5)。辺共有なら中心間距離は 2cos(π/5) = φ。
> 10枚を環にするなら環の半径は φ / (2 sin(π/10)) = φ²。

この誤りのあいだ、生成される五角形は面積の20%が重なっていた。重なったまま並べていたので、続きが描けないのは当然だった。

環の比率が正しいことは、以前に破綻した図（隙間の空いた方）を画素で実測して裏付けた。線幅の分だけセル面積が小さく出る補正を入れると、環内の隣接中心間距離は 1.618 に一致した。

正しい環はこうなる。

- 五角形10枚、隣接は辺共有
- 環の半径 R = φ²
- 中心の穴は正十角形

## 繋がり方は2通りしかない

![](https://static.zenn.studio/user-upload/b578867b9c0a-20260726.png)


環と環がどう繋がるかを、重なりを禁止して全列挙した。結果は明快だった。

**環同士が重ならずに置ける配置は、2通りしか存在しない。**

| パターン | 共有される五角形 | 環の中心間距離 |
|---|---|---|
| 連続共有 | 連続した2枚 | 4.98 |
| 飛ばし共有 | 1つ飛ばした2枚 | 3.078 |

これ以外の距離・角度では、必ずどこかの五角形が重なる。点で接触する配置は存在するが、空間が広くなりすぎて構造にならない。

この2通りしかないという事実は、監督（筆者）が手描きで先に把握していたものであり、AI側の全列挙はそれを機械で追認したにすぎない。帰属は明示しておく。

## 第1層は2種類ある

5個の環による第1層は、2種類作れる。

| 配置 | 環の中心距離 | 五角形 | 共有 |
|---|---|---|---|
| A | φ² | 36枚 | 14枚 |
| B | φ³ | 40枚 | 10枚 |

どちらも重なりゼロ、5回回転対称。両方とも正解である。

層が増えるたび、必要な環は 5, 10, 15 と5ずつ増える。第2層は10個の環が五角形を描き、第1層とは頂点が逆で36度ずれる。そこで連続共有と飛ばし共有の**両方**が必要になる。この2つのパターンの意味が読めれば、2層目以降は自ずと降りてくるはずだ。

## 整数だけで書く

作図コードは整数演算だけで書いた。浮動小数点は、SVGに座標を渡す最後の1箇所にしか現れない。

座標は Z[ζ] の元として持つ。ζ = e^{iπ/5}（36度）で、最小多項式は ζ⁴ − ζ³ + ζ² − ζ + 1 = 0。元は整数4つ組で表す。

```
u = [a0, a1, a2, a3]  =  a0 + a1ζ + a2ζ² + a3ζ³
```

ζ を掛ける操作は、ζ⁴ = ζ³ − ζ² + ζ − 1 で簡約すると整数の置換と加減だけになる。

```python
def z_mul_zeta(u):
    a0, a1, a2, a3 = u
    return (-a3, a0 + a3, a1 - a3, a2 + a3)
```

φ はこの環の中に整数として住んでいる。

```
φ  = ζ + ζ⁻¹ = 1 + ζ² − ζ³   →  [1, 0, 1, −1]
φ² = φ + 1                    →  [2, 0, 1, −1]
φ³ = φ² + φ                   →  [3, 0, 2, −2]
```

平衡φ進数（桁は −1, 0, 1）に直すと、φ² = `100`、φ³ = `1000`。第1層の2種類は、環の中心距離の桁が1つずれただけの関係にある。

構造の生成式は4行で書ける。

```
環の半径        R = φ²
第1層 k番目の環  中心 = D·ζ^(2k)、回転 = 2k
環の j 番目      中心 = D·ζ^(2k) + R·ζ^(2k+j)、向き = 2k+j
五角形の i 番目の頂点  = 中心 + ζ^(向き + 2i)
```

共有される五角形の判定は、整数座標の完全一致で行う。許容誤差の議論が入り込まない。向きの一致は、五角形が72度（=2番地）で不変なので mod 2 で見る。

検証結果は、環内の隣接五角形の中心間距離が全10箇所とも厳密に φ、五角形同士の重なり最大値が厳密に 0 であった。


## 帰属

この記事で述べたことの出所を分けておく。

**監督（筆者）による提示**
- 5角形10個の環という単位そのもの
- 繋がり方は連続共有と飛ばし共有の2通りしかないこと
- 点接触は存在するが空間が広くなりすぎること
- 層ごとに環が5ずつ増えること、第2層は36度ずれて頂点が逆になること
- 第1層が2種類とも正解であるという判定

**AI側の計算**
- 環の半径 φ²、辺共有距離 φ の導出
- 重なりを禁止した全列挙による「2通りのみ」の機械的追認
- 中心に環を置く配置が0通りであることの確認
- Z[ζ] 整数表現による作図コード

AI側が独自に出したものは何もない。誤った環の定義を持ち込み、中心に環を置き、既存の五角形充填（デューラー以来知られている配置）を提示して「これでは」と何度も差し戻されている。この記事の内容は、手描きで先に確定していた構造を、機械が追いついて座標に落とした記録である。
