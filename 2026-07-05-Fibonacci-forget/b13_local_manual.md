# b13_local.py 利用マニュアル

**引継書DB × ローカルLLM (Ollama) 統合ツール — フィボナッチ忘却管理システム**

版: 2026-07-04 / 対象スクリプト: b13_local.py (フィボナッチ忘却実装版)

---

## 1. これは何か

PostgreSQL の `handover` テーブルに蓄積した研究引継書を、ローカルLLM(Ollama + elyza)から活用するためのツールです。役割は三つあります。

第一に**検索エンジン**として、引継書全体を正規表現やプリセット(φ↔√2対立軸)で全文検索します。第二に**簡易RAG**として、質問に関連する箇所だけを抽出してローカルLLMに渡し、出典付きで回答させます。第三に**フィボナッチ忘却管理**として、想起対象を新しい方から 0, 1, 2, 3, 5, 8, 13, 21, … 番目の引継書に限定し、直近の記憶は密に、遠い記憶は疎に保ちます。

構成は次のとおりです。

```
質問 ──→ キーワード/バイグラム抽出
              │
              ▼
   handover テーブル (PostgreSQL: b13db)
              │  ←── フィボナッチ忘却 (--fib) で選別
              ▼
   チャンク分割 → 関連度スコアリング (--decay で黄金比減衰)
              │
              ▼
   上位チャンク (文字数バジェット内) ──→ Ollama (elyza) ──→ 回答+出典
                                └──→ --raw なら表示のみ (Claude/Chappy へ)
```

## 2. 動作要件

- Python 3 + `psycopg2` + `requests`
- PostgreSQL に `b13db` データベースと `handover` テーブル
- Ollama が `localhost:11434` で稼働、モデル `lucas2024/llama-3-elyza-jp-8b:q5_k_m` 導入済み

テーブルのカラム名は起動時に `information_schema` から自動検出します。本文カラムは `content` / `body` / `text` / `document` / `doc` のいずれかがあれば動作し、`version` / `id` / `created_at` / `filename` は無ければ NULL 扱いで続行します。

接続情報は環境変数で上書きできます(未設定ならスクリプト内の既定値):

| 環境変数 | 既定値 |
|---|---|
| B13_DB_HOST | localhost |
| B13_DB_NAME | b13db |
| B13_DB_USER | moroc |
| B13_DB_PASSWORD | (スクリプト内既定) |
| B13_OLLAMA_URL | http://localhost:11434 |
| B13_MODEL | lucas2024/llama-3-elyza-jp-8b:q5_k_m |

## 3. インストール

方法A: `install_b13_local.sh.txt` の中身を丸ごとコピーしてサーバーのターミナルに貼り付ける(ヒアドキュメントで `/home/moroc/b13_local.py` が生成されます)。

方法B: ダウンロードした `b13_local.py` を scp などで転送する。

```bash
scp b13_local.py moroc@サーバー:/home/moroc/
chmod +x /home/moroc/b13_local.py
```

初回はまず一覧表示で動作確認してください:

```bash
python3 b13_local.py --version
```

## 4. モード一覧(クイックリファレンス)

| コマンド | 動作 |
|---|---|
| `--version` | 引継書一覧(id / ver / 日付 / 文字数 / ファイル名) |
| `--version --fib` | 一覧に KEEP(tierN) / forget を併記 |
| `--search REGEX` | 正規表現で全文検索、前後行つき表示 |
| `--preset phi-sqrt2` | φ↔√2 対立軸のプリセット検索(近接ペア強調) |
| `--ask "質問"` | 関連箇所を抽出してLLMに回答させる(RAG) |
| `--next` | 最新引継書から「次にやるべきこと」を回答 |
| `--summary N` | 最新N件(省略時1件)を要約 |
| `--chat` | 対話モード(毎ターンDBを再検索) |

主なオプション:

| オプション | 既定 | 意味 |
|---|---|---|
| `--fib` | OFF | フィボナッチ忘却を適用(ask/summary/chat/version に効く) |
| `--decay` | OFF | `--fib` 時、古い階層ほど関連度を 1/φ ずつ減衰 |
| `--raw` | OFF | LLMを呼ばず抽出結果のみ表示 |
| `--show-context` | OFF | LLMへ渡した参照資料も表示 |
| `--budget N` | 6000 | LLMに渡す参照資料の最大文字数 |
| `--top-k N` | 8 | 使用する最大チャンク数 |
| `--num-ctx N` | 8192 | Ollamaのコンテキスト長 |
| `--context N` | 2 | 検索モードでの前後表示行数 |
| `--model NAME` | elyza 8B | Ollamaモデル名 |
| `--url URL` | localhost:11434 | OllamaのURL |

## 5. フィボナッチ忘却の仕組み

### 5.1 保持則

引継書を新しい順に並べたとき、インデックス **0, 1, 2, 3, 5, 8, 13, 21, 34, 55, …** のものだけを想起対象(KEEP)とし、それ以外を忘却(forget)します。忘却といってもDBからは削除しません。LLMの想起対象から外すだけで、`--search` や `--preset` は常に全件を対象にします(記録は不滅、想起だけが疎になる)。

具体例 — 引継書が v176 まで30件ある場合:

| tier | インデックス | 版 | 位置づけ |
|---|---|---|---|
| 0 | 0 | v176 | 最新(常に保持) |
| 1 | 1 | v175 | 直近 |
| 2 | 2 | v174 | 直近 |
| 3 | 3 | v173 | 直近 |
| 4 | 5 | v171 | 少し前 |
| 5 | 8 | v168 | 少し前 |
| 6 | 13 | v163 | 遠い記憶 |
| 7 | 21 | v155 | 遠い記憶 |

30件が8件に圧縮されます。件数が増えても保持数は対数的にしか増えないため(F(n)≦件数の範囲)、LLMのコンテキストを圧迫しません。どれが保持されているかは `--version --fib` でいつでも確認できます。

### 5.2 黄金比減衰 (`--decay`)

`--fib --decay` を併用すると、tier が1つ深くなるごとに関連度スコアに **1/φ ≈ 0.618** を掛けます。tier0(最新)の重みを1とすると、tier4 で約0.146、tier7 で約0.034。同程度の関連度なら新しい記憶が優先され、古い記憶は「強く関連するときだけ」浮上します。

使い分けの目安:

- `--fib` のみ — 保持対象内では新旧を対等に扱う。過去の理論的決定(例: P*フォークの裁定)を確実に引きたいとき。
- `--fib --decay` — 現在の作業文脈を優先。「いま何をしているか」系の質問に向く。
- どちらも無し — 全件を対等に検索。網羅性が最優先のとき。

## 6. 使用例

### 6.1 日常の想起

```bash
# いま何をすべきか(最新引継書から)
python3 b13_local.py --next

# フィボナッチ記憶で質問(推奨の標準形)
python3 b13_local.py --fib --ask "誕生楕円の短軸と√5の関係はどう確認された?"

# 現在の文脈を優先した質問
python3 b13_local.py --fib --decay --ask "conic幾何の直近の確定事項は?"

# 最新3件の要約
python3 b13_local.py --fib --summary 3
```

### 6.2 検索(常に全件対象)

```bash
python3 b13_local.py --preset phi-sqrt2          # φ↔√2 対立軸
python3 b13_local.py --search "共焦点"            # 単語
python3 b13_local.py --search "ペル.*分子"        # 正規表現
python3 b13_local.py --search "BLIND" --context 5 # 前後5行表示
```

### 6.3 対話モード

```bash
python3 b13_local.py --fib --decay --chat
```

プロンプト `B13>` に質問を打つと、毎ターンDBを再検索して回答します。直前2往復の履歴も渡されます。`:raw` で「検索結果のみ表示」を切替、`:q` で終了。

### 6.4 クラウド連携(三者協働での使い方)

elyza(8B)の回答精度には限界があるため、確定判断が必要な内容はローカル検索×クラウド検証を組み合わせます:

```bash
python3 b13_local.py --fib --ask "α(13^k)の定理の証明状況" --raw
```

`--raw` は抽出チャンクを出典付きで表示するだけなので、その出力をそのまま Claude(Charlie)や Chappy に貼り付ければ、大きいモデル側で検証・整理ができます。`--show-context` を使えば「elyzaの回答+根拠資料」の両方が見えるので、回答の取り違えチェックにも使えます。

## 7. トラブルシューティング

**「handover テーブルが見つかりません」** — `psql -U moroc -d b13db -c '\dt'` でテーブル存在を確認。

**「本文カラムを特定できません」** — `psql -U moroc -d b13db -c '\d handover'` で実カラム名を確認し、スクリプト冒頭の `CONTENT_CANDS` リストに追加。

**「Ollama に接続できません」** — `ollama serve` の稼働と `curl http://localhost:11434/api/tags` を確認。

**「モデルが見つかりません (404)」** — エラー表示に利用可能モデル一覧が出ます。`ollama pull` するか `--model` で指定。

**回答が遅い/途切れる** — `--budget 4000 --top-k 5` で渡す資料を絞る。逆にモデルのコンテキストに余裕があるなら `--num-ctx 16384 --budget 10000` も可(VRAMと相談)。

**関連チャンクが拾えない** — 質問に引継書内の実際の用語(「誕生楕円」「doorway」等)を含めると精度が上がります。`--raw` で抽出結果を見て、キーワード抽出のずれを確認できます。

**回答内容が怪しい** — 8Bモデルは資料があっても混同することがあります。`--show-context` で根拠チャンクを確認するか、`--raw` の出力をクラウド側に回してください。elyzaの回答は「索引付き下書き」の扱いが安全です。

## 8. 設計上の注意(既知の限界)

- 関連度スコアはキーワード+文字バイグラムの表層一致で、意味的な埋め込み検索ではありません。同義語(例:「黄金比」と「φ」)は PHI/SQRT2 プリセット以外では自動で結ばれないため、質問には複数の言い方を併記すると有効です。
- フィボナッチ忘却は「登録順(created_at 降順)」を基準にしています。版番号と登録順がずれている場合、tier の割当も登録順に従います。
- `--decay` の減衰は関連度への乗算であり、tier の深い記憶も強い一致があれば浮上します(完全な忘却ではなく「想起しにくさ」)。
